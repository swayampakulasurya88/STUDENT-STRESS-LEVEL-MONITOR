About Calm Compass

Awareness, not diagnosis

Calm Compass helps students complete a short weekly wellbeing check-in, see their own trend honestly, and lets authorised teachers and counsellors notice who might benefit from a supportive conversation — early, before a quiet bad week turns into a crisis.

What this tool is — and isn't

Calm Compass is an awareness and early-conversation tool. It is not a clinical or diagnostic instrument, it does not detect mental illness, and it does not replace a qualified doctor, psychologist, or counsellor. No score from this app should be treated as a medical or psychological assessment.

It also does not provide emergency monitoring. Nobody is watching responses in real time, and a "Very High" result does not trigger any automatic alert to emergency services.

If you or someone you know is struggling

Reach out to your institution's counselling cell, a trusted teacher, mentor, or family member, or a licensed mental health professional. Talking to a real person early is the single most useful next step this app can point you toward.

In an emergency, or if you feel unsafe right now, contact local emergency services immediately. Do not wait on an app response — call for help.

Privacy & data use

What we collect, why, and who can see it

This page is written in plain language on purpose. If anything here is unclear, please ask before you register.

What's collected

Your name, student ID, contact details, department/year/section, your weekly check-in answers and score, and an optional free-text reflection you choose to write. We don't collect anything beyond what's needed to run the check-in and connect you with support.

Why we collect it

To show you your own trend over time, to let a teacher or counsellor you're affiliated with notice patterns worth a supportive conversation, and to let an administrator keep departments, accounts, and the question bank up to date.

Who can see it
  • You always see your own results, history, and reflections.
  • Teachers/counsellors can see check-in results and trends only for students in their assigned cohort, for the purpose of supportive outreach — never anonymous browsing of the whole student body.
  • Admins can manage accounts and see anonymised, aggregated reports (by department, year, month) by default; access to any individual record is logged in the audit trail.
How long we keep it & how to delete it

Data stays in this browser's local storage for as long as your account exists. To request deletion of your account and check-in history, use the button below or contact — we'll confirm once it's done.

Your consent

Registering requires actively agreeing to this page. You can withdraw consent at any time by requesting account deletion — this does not affect the legality of anything already agreed to.

Project viva reference

C Language & Data Structures concepts used in this project

Calm Compass is implemented in JavaScript, but the logic underneath leans on the same fundamentals taught in Programming in C and Data Structures. Here's exactly where each concept shows up.

Variables & data types

Every student, assessment and question record holds typed fields — strings for names and IDs, numbers for scores, booleans for flags — the same idea as declaring int, char and float variables in C.

Control structures

if / else chains decide the stress category (Low, Moderate, High, Very High) from a score — the same job a C switch-case or nested if block does.

Loops

for / forEach loops walk through every question, student and assessment to build the tables, totals and charts on each dashboard — just like for and while loops in C.

Functions & modular programming

Small reusable functions such as uid() and todayISO() mirror C's approach of breaking a program into single-purpose functions instead of one long block of code.

Arrays

Students, teachers, assessments, departments and questions are all stored as arrays of records — the direct equivalent of arrays of structs in C.

Structures

Each student or assessment object (id, name, department, score, category) groups related fields together — the same idea a C struct is used for.

Searching

Looking up a student by ID or email at login scans the student array until a match is found — a linear search, the same technique taught for searching arrays in Data Structures.

Sorting

Assessment history, admin reports and recent-activity tables are all sorted by date or score before display, using the same comparison-based sorting idea covered in Data Structures.

Queues (FIFO)

The assessment questionnaire presents one question after another in the order it was added — first in, first shown — the same principle behind a queue.

Stacks (LIFO)

Recommendation notes and history entries are shown newest-first — last added, first shown — the same last-in-first-out idea behind a stack.

Hashing-style ID generation

uid() combines a timestamp with a random value to generate a unique key for every record — the same goal a hash-based key generator serves in Data Structures.

File handling (analogue)

Backup export/import and the CSV/PDF downloads read and write structured data as files — the same read/write idea as file handling in C, done through the browser instead of fopen().

This page is a study/viva reference connecting the JavaScript implementation back to core Programming (C) and Data Structures concepts — it isn't literal C code.
